# Extending

The module has no interface to implement: it watches the routes registered with the API provider. This page covers what other modules can rely on.

## Automation nodes

When [`@antelopejs/dms-automation`](/docs/modules/automation/introduction) is loaded, the module registers 5 triggers, 10 actions and 1 data node. Without it, the registration is a silent no-op. The nodes hold no workspace data: none of them takes a `tenantId`.

Each node reads the API settings again before it runs or polls, so it follows a scope or a slow threshold saved on another instance. Routes are named `METHOD /path` (`GET /api/orders/:id`), as the console names them; a runtime route id changes on every start.

### What the nodes record

A run stores each node's output. Request data leaves the console only as a summary: id, time, method, route, status, duration, the error message cut at 300 characters, the `x-request-id`, the source (`tester`, `automation` or none) and a `consolePath` to the request. Client IPs, user agents, headers, bodies, query strings, path parameters and stack traces never enter a run. A request no route answered has no route pattern: its `uri` is the path as requested, path values included. The full request stays one click away through `consolePath`, in the owner-only console. `api.call-route` returns a response body only when `includeBody` is on, cut at 16,384 characters, and never puts the headers of its credential profile in its output; a route that echoes the request's headers in its body hands them to the run with `includeBody`, so leave it off for such a route.

### Triggers

| Trigger | Fires when | Cluster |
| --- | --- | --- |
| `api.route-unhealthy` | A route enters a bad state: `broken` (5xx rate), `slow` (p95 at or above the slow threshold), `warn` (many 4xx) | One node |
| `api.health-changed` | The API verdict changes: `operational`, `degraded`, `down`, `recovered`, `idle` | One node |
| `api.route-recovered` | A route that was `broken`, `slow` or `warn` carries no flag any more | One node |
| `api.request-captured` | A captured request matches the filters | Every node |
| `api.route-registered` | Routes are registered or removed (a deploy, a module loaded, a webhook armed) | One node |

Every trigger outputs a `deliveryId`: two runs with the same one are the same event.

#### Route unhealthy

| Config | Type | Default | Description |
| --- | --- | --- | --- |
| `intervalSeconds` | `number` | `60` (min. 10) | How often the routes are checked. |
| `flags` | `("broken" \| "slow" \| "warn")[]` | `["broken", "slow"]` | The flags that fire. |

Output: `deliveryId`, `routeKey`, `method`, `uri`, `flag`, `errorRate`, `averageLatencyMs`, `requestsLast24h`. The first check after activation only records the current flags.

#### API health changed

| Config | Type | Default | Description |
| --- | --- | --- | --- |
| `intervalSeconds` | `integer` | `60` (10 to 3600) | How often the verdict is read. |
| `verdicts` | verdict list | `["degraded", "down", "recovered"]` | The verdicts whose entry fires. |

The verdict follows the Overview's rules: `degraded` at 1 % of 5xx over 15 minutes, or 5 % of calls at or above the slow threshold; `down` at 20 % of 5xx over 5 minutes; `recovered` for 15 minutes after an incident; `idle` without a call over 24 hours. Output: `deliveryId`, `previousVerdict` and the verdict fields of [Get API health](#get-api-health). The first check only records the verdict; a verdict not watched still becomes the one the next change starts from.

#### Route recovered

| Config | Type | Default | Description |
| --- | --- | --- | --- |
| `intervalSeconds` | `integer` | `60` (10 to 3600) | How often the routes are checked. |
| `flags` | `("broken" \| "slow" \| "warn")[]` | `["broken", "slow"]` | The flags whose end fires. |

Output: `deliveryId`, `routeKey`, `route`, `method`, `uri`, `previousFlag`, `state` (`recovered`, `healthy`, or `idle` when the route has no call left in 24 hours), `incidentStart`, `incidentEnd`, `requestsLast24h`, `errorRate` (0 to 1), `p95Ms`, `routePath`, `checkedAt`. A route moving from one flag to another is not a recovery. A `slow` or `warn` recovery has no event time: two instances checking in different minutes during a leader change can each report it.

#### Request captured

Fires on the instance that served the request, after it is stored. Never fires on a request an automation procedure sent with `api.call-route`, nor on the automation module's own API (`/api/automation/...`), so a procedure cannot trigger itself.

| Config | Type | Default | Description |
| --- | --- | --- | --- |
| `statusClasses` | `("success" \| "client-error" \| "server-error")[]` | `["server-error"]` | The status classes that fire. |
| `statusMin`, `statusMax` | `integer` | | Narrows the statuses. |
| `methods` | method list | all | |
| `routes` | `METHOD /path` list (max. 50) | all | |
| `pathPrefix` | `string` | | Only routes under this path. |
| `minResponseTimeMs` | `integer` | | Only requests at least this slow. |
| `scope` | `"active" \| "all"` | `"active"` | `active`: the routes of the scope setting, read again every minute. |
| `includeUnmatched` | `boolean` | `false` | Also paths no route answers. |
| `includeTester` | `boolean` | `false` | Also the Tester's calls. |
| `maxPerMinute` | `integer` | `30` (1 to 600) | Runs per minute on each instance. |

Output: `deliveryId` (the log id), the request summary, and `droppedBefore`: the matching requests dropped by `maxPerMinute` on this instance since the previous run. Across a cluster, the ceiling is `maxPerMinute` times the number of instances. A request a procedure causes through another route than `api.call-route` (a webhook it calls over HTTP) is not told apart.

#### Routes changed

`api.route-registered` compares the registered routes with the set it stored last in the `route_watch` table, so routes a deploy added are reported after the restart. The first check ever only stores the set. One check serves every activation, at the shortest interval armed.

| Config | Type | Default | Description |
| --- | --- | --- | --- |
| `intervalSeconds` | `integer` | `60` (10 to 3600) | How often the routes are compared. |
| `changes` | `("registered" \| "removed")[]` | both | The changes that fire. |
| `scope` | `"all" \| "own" \| "modules"` | `"all"` | Own routes, module routes, or both. |
| `pathPrefix` | `string` | | Only routes under this path. |

Output, one run per change: `deliveryId`, `registered` and `removed` (each route's `route`, `method`, `path`, `module`, `own`, `controller`, `routePath`; at most 200 each, the controller of a removed route null), `registeredCount`, `removedCount`, `truncated`, `checkedAt`. During a rolling deploy, instances running different versions can report routes removed then registered again.

### Actions

Every action but `api.call-route` only reads (`sideEffects: false`): a test run uses them without asking.

#### Get API health

`api.get-api-health` returns the KPIs of the routes in scope and the Overview's verdict. The optional `days` input (1 to 90) restricts `statusBreakdown` to the last N calendar days.

| Output | Description |
| --- | --- |
| `totalRoutes`, `failingRoutes`, `slowRoutesCount` | Registered routes in scope, and those failing or slow now. |
| `averageLatencyMs` | Mean over every retained day. |
| `callsToday` | Calls of the current calendar day. |
| `errors24h` | 4xx and 5xx of yesterday and today, by calendar day. |
| `statusBreakdown` | `success`, `clientErrors`, `serverErrors`, `total`, from the day statistics. |
| `verdict`, `verdictSince`, `durationMs` | The verdict and since when it holds; null when longer than 24 hours. |
| `incidentStart`, `incidentEnd` | The current or last incident; `incidentEnd` null while it lasts. |
| `serverErrorRate`, `clientErrorRate`, `p95Ms`, `requestsPerMinute` | Over the last 15 minutes; rates in percent. |
| `calls24h`, `serverErrors24h` | Over the rolling last 24 hours, from the logs. |
| `recoveredRoutes`, `routesNeedingAttention` | Route counts. |
| `scope` | The scope the figures were computed on. |
| `logsPath` | The incident's 5xx in the logs, else the last 24 hours of 5xx. |
| `checkedAt` | |

#### Query request logs

`api.query-request-logs` returns request summaries under the active scope, newest first. Inputs: `route` (`METHOD /path`), `routeId`, `uri`, `method`, `statusClass` (`success`, `client-error`, `server-error`), `statusMin`, `statusMax`, `since` (inclusive), `until` (exclusive), `requestId`, `errorMessage` (part of the message, any case), `cursor` and `limit` (default 50, max. 200). Without `since`, a scoped query reads the last 30 days. Pass the `nextCursor` it returns as `cursor` to read the next page.

#### Call API route

`api.call-route` calls a registered route of the API over HTTP, for synthetic checks. It reaches any registered route except the console's, the DMS's own (`/dms`, `/api/realtime`, its Settings, session, account (`/api/auth/...`) and onboarding endpoints), the automation module's API and page layouts. A route under a DMS prefix whose module cannot be told is refused too. The path is checked again once its parameters are filled: a call that another registered route could answer, when that route is refused, fails. There is no free URL.

| Input | Type | Default | Description |
| --- | --- | --- | --- |
| `route` | `METHOD /path` | | Required. |
| `pathParams` | `object` | `{}` | Values of the `:name` segments, encoded; `.` and `..` are refused. A route with a composite (`file.:ext`) or catch-all (`::rest`) segment cannot be called. |
| `query` | `object` | `{}` | Query string values. |
| `body` | JSON | | At most 64 KB; refused on `GET` and `HEAD`. Null sends none. |
| `credential` | `string` | anonymous | A profile of [`automationCredentials`](/docs/modules/api/configuration#options); empty or null calls anonymously. |
| `timeoutMs` | `integer` | `10000` (100 to 30000) | |
| `includeBody` | `boolean` | `false` | Return the response body. |

Output: `ok` (status 200 to 399), `statusCode` (null on a timeout or a network error), `durationMs`, `error`, `contentType`, `body` (with `includeBody` only, parsed when JSON, cut at 16,384 characters), `bodyTruncated`, `requestId`, `logsPath`, `dryRun`.

Without a profile the call carries no cookie and no `authorization`: a guarded route answers 401. The call goes to `automationCallBaseUrl`, else to the DMS `apiBaseUrl`. It is sent with `x-request-id: auto-<runId>-<nodeId>` and a token the server signs: the logs show it with an **Automation** badge, and it stays out of the statistics, the health and the Documentation tab. In a test run the action checks the route, the parameters, the body, the profile and the origin, then returns without calling.

#### Reads

| Action | Inputs | Returns |
| --- | --- | --- |
| `api.list-unhealthy-routes` | `flags`, `includeRecovered`, `limit` (default 50, max. 200) | Routes in a bad state under the active scope, worst first: verdict, 24-hour counts, error rate, p95, incident, top error, `routePath`; and `total`. |
| `api.list-incidents` | `period` (default `last-7-days`) or `since` / `until`, `route`, `ongoingOnly`, `limit` (default 20, max. 100) | Each route's runs of 5xx, as the Overview's journal splits them (a pause of 15 minutes ends one), newest first, with their peak per minute, top error and `logsPath`. |
| `api.get-route-statistics` | `route`, `period` (default `last-24h`) or `since` / `until`, `compare` | One route's calls, 4xx, 5xx, error rate in percent, average, p95 and max latency, and the same for the period before. `found` is false for a route no handler answers. |
| `api.get-route-errors` | `route`, `period` or `since` / `until`, `statusClass`, `limit` (default 10, max. 50) | One route's errors grouped by status and message, most frequent first, each with its `logsPath`. |
| `api.get-request-log` | `id` or `requestId` | One request summary, with `routeRegistered` and `responseBodySize`; the newest of the requests sharing a request id, and `matches`. Not found is `found: false`, not a failure. |
| `api.get-route-detail` | `route` | A route's module, scope, controller, authentication (`required`, `probable`, `unknown`), 401s of the last 7 days, declared parameters (no example values), 24-hour state, first and last call, `routePath`, `testerPath`. |
| `api.list-routes` | `scope` (`active`, `own`, `modules`, `all`), `pathPrefix`, `methods`, `includeAuth`, `limit` (default 100, max. 500), `offset` | Registered routes with their module, 24-hour state and last call; with `includeAuth`, their authentication, read from each handler's code (slower). |

Reads of a named route ignore the scope. The others read the routes of the active scope.

### Data node

`api.console-link` builds the path of a console page, and its URL when the DMS knows its `clientBaseUrl`. `target`: `overview`, `route`, `tester`, `request`, `logs`, `routes` or `settings`; the other inputs (`route`, `tab`, `requestLogId`, `statusTab`, `error`, `requestId`, `since`, `until`, `period`) narrow it. Output: `path`, `url`, and `valid`, false when the target's required input is missing (`path` is then the page's root).

## Access

The console is for the platform owner only. Its pages belong to the `api` module, and the DMS grants a module page's permissions to the owner alone: they do not appear in the role editor, and a role cannot be given the console or any block of it. A member who calls a console route gets a 403.

Each block is declared with `.meta({ name, icon })`, and each route is guarded with `@AuthUserWithPermission(<block>)` for the block it feeds. The 403 names that block's permission id.

## Own routes and module routes

The console sorts each route by where its controller comes from: **own routes** from the project's code, **module routes** from installed AntelopeJS modules. The [scope setting](/docs/modules/api/usage/settings#route-visibility) picks which ones the pages watch. A distributable module that adds routes shows up under **Module routes**.

## Make the documentation tab accurate

The Documentation tab infers a route's contract from its handler and its traffic:

- Guard routes with the DMS auth decorators, or name your auth middlewares to match `authMiddlewareNamePatterns` (`^auth_`, `^requireAuth`, `^session_` by default), so the route reads as authenticated.
- Parameters and bodies come from captured client requests. Make a representative call from your application or an API client, then open the Documentation tab. Tester calls are excluded from contract inference; they cannot populate missing examples.

## Link to the console

| Link | Opens |
| --- | --- |
| `/modules/api/routes?route=<METHOD> <path>&tab=statistics\|documentation\|tester` | A route on one of its tabs |
| `/modules/api/logs?record=<id>` | A request in its drawer, by its log id |
| `/modules/api/logs?requestId=<x-request-id>` | The requests sent with that request id |
| `/modules/api/logs?since=<iso>&until=<iso>` | The requests of a time range |
| `?api.period=last-hour\|last-24h\|last-7-days\|last-30-days` | A page on a period |
| `?api.compare=previous-period\|none` | The Overview or Routes against the period before, or alone |
| `?live=0` | A page paused |
