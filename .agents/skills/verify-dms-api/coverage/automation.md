# Coverage: automation

The playground's fixture module stands in for the automation provider when a journey restarts the backend with `VERIFY_API_AUTOMATION=1`: it keeps the node types the module registers and runs `execute` and `activate` through `/verify-api/nodes`. The automation runtime itself is not loaded.

| Source | Documented behaviour | Journey | Check |
|---|---|---|---|
| docs/5.extending.md (Automation nodes) | Without `@antelopejs/dms-automation` the registration is a silent no-op | `without-the-automation-module-the-registration-is-a-silent-no-op` | `the log says the optional automation interface has no provider`, `no error line names the automation nodes`, `no line says dms-api failed`, `the console answers` |
| docs/5.extending.md (Automation nodes) | The module registers three nodes: `api.route-unhealthy`, `api.get-api-health`, `api.query-request-logs`; the trigger runs on one node of a cluster | `the-module-registers-its-three-nodes-with-their-documented-inputs` | the registered ids, `singleton`, and each declared input: `days` minimum 1, `limit` default 50 maximum 200, the three status classes, `intervalSeconds` default 60 minimum 10, the flags and their default, the output fields |
| docs/5.extending.md (Route unhealthy trigger) | Fires when a route enters a bad state by the API health rules; `flags` broken, slow, warn with default broken and slow; `intervalSeconds` default 60, minimum 10; output routeKey, method, uri, flag, errorRate, averageLatencyMs, requestsLast24h | `route-unhealthy-fires-on-the-flags-it-watches-and-never-faster-than-ten-seconds` | four triggers armed before a failing, a noisy and a slow route appear: `broken` only gets the failing route, `warn` only the noisy one, the default gets broken and slow, all three flags get three; the output of a broken route; an interval of 1 second fires nothing in the first seconds and fires after 10 |
